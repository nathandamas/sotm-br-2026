# OpenStreetMap Mapping Maturity and Urban Resilience — Petrópolis, Brazil

Reproducible geospatial research workflow for analysing the spatial and temporal maturity of OpenStreetMap (OSM) data in Petrópolis, Rio de Janeiro, Brazil, with emphasis on its potential use in urban resilience, disaster-risk and humanitarian mapping applications.

## Overview

This repository contains the computational workflow developed for the SotM Brasil 2026 research project. The analysis reconstructs OSM mapping trajectories on a regular 1 km grid and derives cell-level indicators describing mapping activity, temporal development and maturity. These indicators are subsequently explored, classified and interpreted to produce a spatial typology of OSM mapping maturity.

The repository is designed to preserve the analytical chain from input validation and spatial-grid construction through ohsome API data acquisition, time-series construction, indicator derivation, typology development and generation of article-ready outputs.

## Study area

The case study is Petrópolis, in the state of Rio de Janeiro, Brazil. Spatial analysis is conducted using an IBGE-based 1 km grid intersecting the study area.

## Analytical workflow

The workflow is organised into 13 sequential Jupyter notebooks:

1. `01_validate_ibge_input_data.ipynb` — validates the IBGE spatial input data.
2. `02_build_ibge_1km_grid.ipynb` — constructs the 1 km analytical grid for Petrópolis.
3. `03_prepare_ohsome_boundaries.ipynb` — prepares grid geometries for ohsome API requests.
4. `04_query_ohsome_test_cells.ipynb` — tests the ohsome query procedure on a subset of cells.
5. `05_query_ohsome_all_895_cells.ipynb` — retrieves historical OSM information for the complete analytical grid.
6. `06_build_monthly_osm_timeseries.ipynb` — constructs monthly OSM time series at cell level.
7. `07_build_osm_maturity_indicators.ipynb` — derives mapping-maturity indicators.
8. `08_explore_osm_indicator_structure.ipynb` — explores the statistical structure of the indicators.
9. `09_build_osm_cell_typology.ipynb` — constructs the preliminary cell typology.
10. `10_interpret_osm_typology.ipynb` — supports interpretation and diagnostic assessment of the typology.
11. `11_finalize_osm_typology.ipynb` — produces the final typology.
12. Notebook 12 — generates the final cartographic/analytical outputs used in the study.
13. Notebook 13 — generates article-ready tables and associated reporting products.

The numbered notebooks should be interpreted as a reproducible analytical pipeline rather than as independent analyses.

## Reproducible outputs

Executed notebooks and their generated products are materialised under:

```text
data/output/notebooks/
```

Each numbered directory corresponds to one stage of the workflow. `data/output/notebooks/manifest.csv` provides an inventory of the materialised files and their sizes.

Final publication-oriented products are separated from intermediate notebook outputs:

- `data/output/figures/` — maps and figures;
- `data/output/tables/` — analytical and manuscript tables;
- `data/output/notebooks/` — execution records and intermediate/final notebook products.

This separation is intentional: the `notebooks/` directory contains the analytical source code, whereas `data/output/notebooks/` preserves products generated by executed workflows.

## Main data and technologies

The workflow relies primarily on:

- OpenStreetMap historical data;
- the ohsome API for OSM history aggregation;
- IBGE geospatial data for the spatial analytical framework;
- Python and Jupyter notebooks;
- GeoPandas/Pandas and the broader Python geospatial ecosystem;
- GitHub Actions for reproducible remote execution and preservation of computational outputs.

## Reproducibility

The project records computational results produced by the notebook pipeline and GitHub Actions. Because external OSM/ohsome data services and upstream datasets can evolve, exact reproduction should use the versions, parameters, intermediate products and execution artefacts preserved in this repository whenever possible.

The analytical sequence should normally be executed from Notebook 01 through Notebook 13 because downstream notebooks depend on products generated by preceding stages.

## Research context

The repository supports research on volunteered geographic information (VGI), OpenStreetMap contribution histories, spatial data quality and mapping maturity. The central methodological premise is that the temporal trajectory of OSM contributions contains information that can complement static measures of map coverage when assessing the maturity and potential reliability of volunteered geographic information.

The Petrópolis case study provides an empirical setting in which these dynamics can be examined in relation to spatially heterogeneous urban and peri-urban environments and contexts relevant to disaster-risk and resilience applications.
